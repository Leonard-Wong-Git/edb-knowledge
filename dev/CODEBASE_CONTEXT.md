### OpenAI API
- Purpose: (1) embedding-based semantic topic detection; (2) circular analysis generation
- Backend usage: `backend/src/lib/embeddingClient.ts` (embeddings), `backend/src/lib/llmClient.ts` (LLM)
- Embedding model: `text-embedding-3-small` (fixed in embeddingClient.ts)
- LLM default model: `gpt-4.1-nano` (configurable via `OPENAI_MODEL` env var)
- Notes:
  - LLM implementation targets the Responses API (`client.responses.create`)
  - Embedding implementation uses standard Embeddings API (`client.embeddings.create`)
  - Anchor embeddings (6 topics) are cached in-process after first request — no re-embedding per query
- **Vision OCR usage (S147, offline one-off tooling — NOT a backend runtime path)**:
  - Endpoint: `POST https://api.openai.com/v1/chat/completions` (Chat Completions, image input)
  - Model: `gpt-4o` (default in `dev/ocr_extract.py --model`); params `temperature=0`, `max_tokens=4096`, `image_url` with `detail:"high"` (base64 PNG data URL)
  - Auth: `Authorization: Bearer <OPENAI_API_KEY>` (read from `backend/.env`, never logged)
  - Response path: `choices[0].message.content` (transcribed text)
  - Purpose: OCR scanned/image-only or CID-mojibake EDB PDFs that have no extractable text layer (e.g. `mce_framework_2008` 8-image pages, g38 family) into the canonical vault format for Channel B ingest. Draft quality — traceability preserved via chunk `url`+`=== Page N ===`.
  - Test-verified: 2026-06-07 (Claude_20260607_1336) — `mce_framework_2008` 8 pages OCR'd, U+FFFD=0, ingested +13 chunks, direct RPC retrieval confirmed.

### Supabase (Channel B pgvector)
- Base URL: `https://<project-ref>.supabase.co` (project ref in `backend/.env`/Render env; live = `youkcekbrbywuqjxgibe`)
- Version: PostgREST v12 (managed by Supabase); Postgres 15+ with pgvector
- Auth: anon key (frontend bundle / backend query-side, `SUPABASE_ANON_KEY` in Render env) + service_role key (backend upload-side, `SUPABASE_SERVICE_KEY` in `backend/.env`; never exposed to frontend)
- Required params: for RPC `/rest/v1/rpc/match_wiki_chunks` body = `{query_embedding: <string of stringified float64 array via toFixed(8)>, match_threshold: number, match_count: number|null}` (send string not vector array, internal `::vector` cast — bypass supabase-js)

- Response path: RPC returns TABLE(id text, hash text, text text, source_id text, title text, url text, topic text, content_type text, fact_type text, role text, school_level text, reference_year text, score double precision)

The vault serves both: statistical facts feed LLM-wiki search and point users to source URLs; policy facts continue to feed `role_facts.json`
