PART 1八問八答

Q1Home 第一眼 surface 乜？錯咗點知？
Template gallery first, search 做 sticky header。JOB-B（文件生成）係 80% 時間付出，JOB-A（查政策）可經同一個搜尋框 fan-out。 錯判訊號：template_card_click_rate < 15%、search_to_doc_conversion < 8%、用家返 home 後 3 秒內再打開 search（即 template 冇答到佢）。7 日 rolling 跌穿 threshold 就 swap 做 search-first。
Q2「問答」vs「文件生成」點放置？
同一個 omni-input，後台按 intent 分流；Q&A 視為「只有一段、唔存盤」嘅 document。UI 層 template gallery 係主 surface，input 框有 placeholder 例示：「搜政策 · 生成文件 · 按校本 metadata 套用」。分流 classifier 用 query 長度 + 關鍵詞（生成 / 做份 / template）+ 可選下拉 override。結果：用家唔需要 mental switch，但文件 canvas 同 Q&A 卡片視覺上分得開（前者全頁 doc，後者 inline answer sheet）。
Q3三通道（A/B/AB）UI 處理？
選 (b) 折疊做「進階」，default 係 AB，後台 state 仍叫 'AB'。
  • (a) 完全隱藏：最乾淨，但 EO / IT 想手動審核冇 escape hatch，policy_signals 工作流會受影響。
  • (b) 折疊「進階」：✓ default 無認知負擔；power user 可 pin。UI label 改叫「只用已核實事實 / 加入 EDB 原文 / 兩者都用」——code 內仍係 A/B/AB。
  • (c) 三選一：保留技術 framing，對 P1 40+ 歲科主任係 dead weight。
Q4Citation surface 方式？
Inline 上標 + hover card + 右 side panel 三層合併。段落內 [3] 風格上標（keyboard accessible）；hover / tap 彈 80–120 字節錄 + 連結；右 panel 係 session-wide source ledger（可 pin / 按 topic 排）。Mobile 冇 hover，tap 變 bottom sheet。原則：citation 係文件一部分，唔係附錄——export Word / PDF 會保留上標 + 尾注。
Q5Loading state 點避免 ChatGPT streaming 感？
唔 stream token，改做「文件施工中」隱喻：skeleton layout（section 標題、段落 block、表格 placeholder 全部 greyed-in）＋ 頂部一條 step 2 of 5 · 抽取 EDB 第 112-118 號通告 嘅 progress track。每完成一個 section 就一次過 fade-in，而非逐字出。冇 typing cursor、冇 animated dot、冇「思考中…」。ETA 顯示實際秒數（例：~18s）。
Q6Admin 同 public 分唔分 route？Auth？
分 /admin/*，SSO-only（EDB Microsoft 365 / Azure AD），client 端 role gate，server 端 API middleware 複核。 Public routes：/, /t/:id, /d/:id, /q。 Admin routes：/admin/signals, /admin/sources, /admin/templates。 唔用 magic link，避免校園 shared device lingering session；admin session idle 15 min 自動登出。
Q7前端架構？Trade-off？
Vite + React + TanStack Router（file-based）+ TanStack Query + Zustand（UI state）。
  • 繼續 4,048 行 app.html：debt 繼續累，template gallery / admin / draft canvas 難 code-split，mobile bundle 大。
  • Multi-page（MPA）：SEO 好但 public site 唔需要 SEO；template 切換 / draft canvas 之間要共享 source panel state，reload 會 disrupt。
  • Vite file-based SPA：✓ route split、✓ 保留 single source panel、✓ 可漸進 migrate（見 2.7）。唯一代價：build pipeline 比 static HTML 複雜，但 GitHub Pages 仍 host 到 static output。
Q8Mobile / desktop 一份定兩份？
一份 responsive，但 draft canvas 同 signal review 有 desktop-specific layout（breakpoint ≥ 1024px）。理由：80% mobile 集中喺 home / template pick / Q&A，呢啲 single-column 天然 OK；draft canvas 左右雙欄（文件 + sources）mobile 收埋做 tab switcher + bottom sheet。分兩份 codebase drift 風險太大，唔值得。

視覺

唔用 placeholder 代替 label、唔 auto-suggest AI 答案入 field（呢度係 metadata，唔係 prompt）、唔加 sparkle「智能填寫」。

PART 2.6State Patterns

empty

Zero draft / zero match。文案講下一步，而非「問我任何嘢」。

copy：「未有草稿。由 template 開始，或直接查政策。」+ 2 按鈕

generating

Step-based progress，section skeleton，實際秒數 ETA。冇 streaming、冇 dot loader。

組件：ProgressTrack（5 步）· SectionSkeleton · SourceReadoutList

generated

全段 fade-in；頂部 toast 已完成 · 引用 7 個來源 · ~22 秒；自動 scroll 去 §1 而非頁尾。

toast 4s 自動收

error

磚紅而非 alarm red，明確講邊一步死：步驟 2：抽取 EDB 原文失敗（network 408）。提供 retry / fallback A-only / 交給知識團隊。

發送 policy_signals.json pending

stale-source

段落級 + 來源 panel 雙重標記：⚠ 2026-03 有修訂。一鍵「重新生成引用 stale 段」。

顏色：--stale (#8A7A3B)，非紅

offline

頂部 bronze ribbon：離線模式 · 上次同步 04-19。可用：快取 template + 核實事實；不可用：channel B（EDB 原文即時搜索）。

唔自動 retry fetch，避免浪費校園 bandwidth

PART 2.7前端架構 Recommendation

Stack

  • Framework：React 18 + TypeScript
  • Build：Vite 5（output 仍係 static，可 host GitHub Pages / EDB 內網 static server）
  • Routing：TanStack Router（file-based，type-safe search params，天然支援 /admin/* lazy chunk）
  • Data：TanStack Query（stale-while-revalidate、offline-first cache、retry policy 可按 endpoint 調）
  • UI state：Zustand（draft canvas 嘅 selection / right panel open / source ledger）；盡量唔用 Redux
  • Forms：react-hook-form + zod（RequirementField 驗證）
  • Editor：Tiptap（ProseMirror）for draft canvas — 支援 inline 上標 node、section node、citation mark
  • Styling：Vanilla CSS + CSS variables（tokens 檔）；唔上 Tailwind（教育 IT 易於人肉 audit）
  • Auth (admin)：MSAL.js（Azure AD）→ server middleware 複核 JWT

對 frozen backend 點接 —— Adapter layer

FROZEN 以下 module 係「接口必須一樣」嘅 adapter boundary。Frontend 任何層都唔可以繞過呢層直接 hit endpoint。

│  ├─ template.ts
│  ├─ document.ts

Rule：adapter 層嘅 input/output type 一 byte 都唔改；domain 層允許 derive / reshape，但永遠由 adapter 嘅原始 payload 出發。例如 useTemplates() 係將 knowledge.json 嘅 7 個 topic × 8 個 role bucket flatten 成 UI 好用嘅 TemplateCardModel[] —— 但 adapter 回傳嘅仍然係 spec 原 schema。Circular System 姊妹 repo 睇到嘅係冇變嘅 JSON / endpoint。

const channelLabel = {

  B:  '加入 EDB 原文',

Migration path（由 app.html 4,048 行漸進遷移）

  1. Week 1 — Vite shell + adapter lift：新 repo edb-kb-web/ 起 Vite + TanStack Router 骨架；將現時 app.html 嘅 fetch 邏輯原封不動搬入 infra/adapter/*，寫 contract tests（Playwright fixtures 比對 JSON shape 同 HTTP 行為）。現有 app.html 繼續生產跑，URL 不變。
  2. Week 2 — Home + Template gallery：/ 同 /t 兩條 route 用新 stack 上線，deploy 到 /v2/* path，老路徑保留。Telemetry 比對 template_click、search_to_doc。
  3. Week 3 — Draft canvas + Tiptap：/d/:id 上線，舊 app.html chatbot view 改 redirect 到新 /q（Quick Q&A modal route）。
  4. Week 4 — Admin split：/admin/* chunked、MSAL wired、policy_signals adapter 寫入路徑同姊妹 repo contract 對齊；舊 app.html 下線。
  5. Week 5 — Cleanup：刪 app.html；所有 URL 301 去新 route；/v2/ 前綴移除。

Rewrite vs 漸進：我選漸進 —— 4,048 行裡面有 hard-won edge case（offline、Circular System signal 拍拖、搜索結果 merge 規則），rewrite 會 regress。但 UI 層 100% 新寫，舊 HTML 唔再維護。

本校依據《教育局通告第 02/2023 號 — 資助學校採購程序》1及《學校行政手冊 2024》2，並結合本校辦學使命，制訂《校本採購指引 2026-27》，以規範日常物資、服務及工程採購事務，適用於所有全額或部分由政府津貼支付之採購項目。

§2　採購原則
(a) 物有所值：每項採購須在同等質素下取得最低整體成本3。
