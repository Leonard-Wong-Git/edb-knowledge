## 3. 結束訪談（Day 14，45–60 分鐘）

**形式**：面對面或 video call，**錄音**（要 P1 同意）。

### 3.1 暖身（5 分鐘）

直接講：「坦白程度 > 客氣。我係要知道個系統幾時冇用，唔係聽你讚。如果完全冇用，**呢個答案對我更有價值**。」

### 3.2 事實問題（15 分鐘）— 先事實後主觀

| 問題 | 目的 |
|---|---|
| 過去 14 日，你**估計**用咗幾多次？ | 對比 backend log，看佢是否誇大/低估 |
| 你記唔記得**第一次**打開系統係想解決咩問題？ | 測動機真實性 |
| 你記唔記得**最近一次**打開係咩時候、咩原因？ | 測最近記憶，看 recency |
| 你**唔記得打開**過系統嘅情況，有冇？（即：你平時想問 EDB，但冇諗起用我呢個） | 最重要——測 top-of-mind |
| 呢 14 日你用過邊啲**其他**方式查 EDB 嘢？（問人、Google、EDB 網站、GPT） | 測真實替代選項 |

### 3.3 體驗問題（15 分鐘）

| 問題 | 目的 |
|---|---|
| 三個檢索方式（人工審核/智慧搜索/綜合檢索），你分唔分到之間嘅唔同？ | 測 IA clarity |
| 你最信任邊個通道嘅答案？點解？ | 測信任來源 |
| 有冇一次系統答案**錯**，令你 mislead？ | 測真實風險 |
| 有冇一次答案**正確但唔夠用**，要你再問人？ | 測 completeness gap |
| 手機上用過嗎？咩情境？ | 驗 mobile responsive 價值 |

### 3.4 Killer Question（最重要）

> **如果呢個系統聽日 shut down，你會覺得可惜嗎？咩情況下會可惜？**

- 「會，因為我已依賴佢做 X」→ 🟢 真正有用
- 「有少少可惜，但都有其他方法」→ 🟡 可有可無
- 「坦白講唔會，因為我冇用過幾次」→ 🔴 失敗，但**呢個答案最值錢**

### 3.5 Pricing sanity check（可選，10 分鐘）

> **純假設**：如果系統要交月費$20 HKD 先用得，你會畀嗎？

- 會 / 可能會 / 不會
- 如果不會，要你覺得值得嘅話，要加 / 改咩？

（**注意**：唔係真要收費，只係 willingness-to-pay signal；肯畀錢嘅真實指標 > 口頭讚賞。）
